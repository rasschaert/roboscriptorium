# Models tried, by role

Every model screened for a role, with its verdict, so a candidate is not tried twice.
The roles table in AGENTS.md names the ones in use; a new model is tried *for a role*,
measured against the one playing it, and recorded here (in use, candidate, or unfit)
with a dated line in [decisions.md](decisions.md).

OCR scores on "Teirlinck 12 pages" come from the retired pre-reform bench and
are history only. On modern Dutch (Goede dochter pp. 9–64, 1,622 body lines,
typesetting folded) the text layer reads 0.21% CER, glm-ocr 0.25%, tesseract
0.29%, qwen3.8 0.17%; re-bench candidates there and on the Boekenweek books and Reis om mijn
schedel before choosing an OCR model.

## Setup

How the models in use are installed and served, where it isn't a plain `ollama pull`.
AGENTS.md (Environment) keeps the machine's rules.

- **Ollama 0.40.9** since 2026-10-22 or 23 (updated without a record; 0.40.6 from 2026-10-18,
  0.40.3 before, 0.35.1 before 2026-10-06). Since
  0.40.4 a decision model made from a GGUF by a Modelfile is refused ("a format that is
  no longer supported", ollama/ollama#18917: it needs llama.cpp's decision metadata in
  the GGUF itself), which retired winnow-ollama:e4b; imajev:4b, off, is made so too.
  After an update the decision models' cached answers are asked again
  (`experiments/probe_decider_drift.py` for the roles, `probe_judge_drift.py` for the
  judges): on 0.40.9 clef-flash the same role on 80 of 80, clef:27b and Winnow-12B the
  same pick on 60 of 60 each (Goede dochter). On 0.40.6
  clef:27b gave the same pick on 60 of 60 OCR-check questions, clef-flash the same role
  on 80 of 80 (`experiments/probe_decider_drift.py`), Winnow-12B the same pick on 157 of
  158 suspects of the token probe (the one a near-tie, 0.41 against 0.405). Ollaya was
  uninstalled on 2026-10-08; every model runs on Ollama.
- **Context length 32k** (the user, 2026-10-13), for glm-ocr reading whole pages:
  llama.cpp's four slots share the context, so 8k left each request ~2k, too little for
  a page. 128k only held memory for KV caches; readings are the same either way.
- **`OLLAMA_NUM_PARALLEL=4`**, set with `launchctl setenv` (the app reads it when it
  starts; `launchctl unsetenv` removes it): the llama.cpp-served models (glm-ocr,
  clef-flash, Winnow-12B) get four slots, which doubles glm-ocr's throughput and changes no
  reading; the MLX runner behind the nvfp4 builds (qwen3.8, clef:27b) serves one request
  at a time whatever the setting, and the decision models gain nothing either way.
- **`clef-flash:9b`** was pulled again on 2026-10-15 (digest `0a2a05d6`): it answers the
  cached line-role questions as the old build did (`experiments/probe_decider_drift.py`).
- **Winnow-12B** (`hf.co/Piotr1215/Winnow-12B-GGUF:Q4_K_M`, pulled as it is): the
  pipeline's second judge, named `tokens:hf.co/Piotr1215/Winnow-12B-GGUF:Q4_K_M` in
  `check_model`. `clients/decide.py`'s `TokenClient` renders the question in the layout
  winnow was trained on (EldanRing/winnow-inference `native/protocol.h`), sends it raw
  to `/api/generate` and reads the next token's log-probabilities over the option
  labels, so it needs no `decision` capability and no Modelfile.
- **`winnow-ollama:e4b`** (out of use since 2026-10-18; its Modelfile,
  `modelfiles/winnow-ollama-e4b.Modelfile`, is kept): winnow:e4b's GGUF
  (`hf.co/EldanRing/Winnow-E4B:Q8_0`) given `CAPABILITY decision`, `CAPABILITY vision`
  and an empty `TEMPLATE {{ .Prompt }}`, copied from clef-flash's.
- **`imajev:4b`**: mindchain's imajev-4b (`hf.co/mindchain/imajev-4b-GGUF:Q8_0`) made a
  decision model with `modelfiles/imajev-4b.Modelfile`. The candidate for plates without
  a caption; off in the pipeline. The 2B and 9B were deleted after their screen (their
  Modelfiles and readouts remain).
- **imajev on llama.cpp** (Homebrew, 0.6.0): `llama-server` runs imajev for the judge
  tryout on Ollama's own blobs, its readout applied in `clients/llama.py`
  (`experiments/llama-serve.sh <size> [port]`), because Ollama's systemone takes no images
  for GGUF models. Its image placeholder is random per start; read it from `/props`
  (`media_marker`). Readouts and calibrations in `work/models/imajev/` (from
